# Deployment

```
Phone / browser ──► https://gym-app.snitin322.workers.dev  (Cloudflare Worker)
                       ├─ /api/*  ──► https://onthec-api.onrender.com  (Render, Singapore)
                       │                  └─► Neon Postgres (Singapore)
                       └─ everything else ──► static PWA files (apps/web/dist)
```

The app and API share one address (the Worker forwards `/api`), so the login cookie is
first-party and works on iPhone Safari.

| Piece | Where | Config in repo | Deploys when |
|---|---|---|---|
| Web app + Worker | Cloudflare Workers `gym-app` | `wrangler.jsonc`, `apps/web/worker/index.ts` | push to `main` (Workers Builds) |
| API | Render web service `onthec-api` | `render.yaml` | push to `main` (auto-deploy) |
| Database | Neon project (Singapore) | `apps/api/prisma/` | migrations run on every API start |

---

## One-time: create the API on Render

1. Log in to **https://dashboard.render.com**.
2. **New +** → **Blueprint**.
3. Connect GitHub if asked, and pick the repository **Snitin322/gym-app**. Branch `main`.
4. Render reads `render.yaml` and shows the service **onthec-api** (free, Singapore).
5. It asks for the values marked "sync: false". Copy them from `apps/api/.env` on your laptop
   (don't paste them into chat):

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Neon Singapore, **pooled** string (host contains `-pooler`) |
   | `DIRECT_URL` | Neon Singapore, **direct** string |
   | `OTP_PROVIDER` | `console` until the WhatsApp template is approved, then `whatsapp` |
   | `WHATSAPP_PHONE_NUMBER_ID` | from Meta (can be left empty while `OTP_PROVIDER=console`) |
   | `WHATSAPP_ACCESS_TOKEN` | permanent System User token (see `docs/WHATSAPP_SETUP.md` Part 6); empty while `console` |

   `JWT_SECRET` and `OTP_SECRET` are generated by Render automatically.
6. Click **Apply** / **Deploy Blueprint**. The first build takes ~5 minutes.
7. When the service shows **Live**, copy its URL at the top of the service page
   (e.g. `https://onthec-api.onrender.com` — Render adds a suffix if the name is taken).
8. Check it: open `<that URL>/api/v1/health` → `{"status":"ok","db":"ok",...}`.
9. If the URL is **not** exactly `https://onthec-api.onrender.com`, update `API_ORIGIN` in
   `wrangler.jsonc` and push.

### Reading login codes while `OTP_PROVIDER=console`

Render dashboard → **onthec-api** → **Logs**. Request a code in the app, then look for
`[console OTP] Onthec Gym login code for +91******1234: 123456`.

Switch to WhatsApp later: **Environment** → set `OTP_PROVIDER=whatsapp` and the two
`WHATSAPP_*` values → **Save changes** (Render redeploys).

## Free-tier behaviour

- Render free services **sleep after ~15 minutes** without requests. The next request wakes it
  and takes **30–60 seconds**; after that it's fast. Upgrade to the Starter plan before members rely on it.
- Neon free projects also pause when idle; the first query after a pause takes ~1 second.

## Day to day

- Push to `main` → Cloudflare rebuilds the app + Worker, Render rebuilds the API and applies any new migrations.
- Production secrets live only in the Render (and Cloudflare) dashboards, never in the repo.
- Seed the owner in production once from your laptop (with the Singapore URLs in `.env`): `pnpm db:seed`.
